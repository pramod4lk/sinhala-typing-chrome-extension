# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Chrome extension (Manifest V3) that converts **Singlish** (romanized/phonetic Sinhala typed on an English keyboard) into Sinhala Unicode as you type, in any text field on any web page. Example: typing `mama gedhara yanavaa` produces `මම ගෙදර යනවා`. Current release: **v0.1.0** (see "Releasing").

## Constraints

- **No build step, no npm dependencies.** Plain JavaScript loaded directly by Chrome. The extension root is the repo root (where `manifest.json` lives).
- Manifest V3 only. The background script is a service worker, so keep no state in globals there; persist in `chrome.storage`.
- The only permission is `storage`. Content scripts use `"matches": ["<all_urls>"]`, `"all_frames": true`, `"match_about_blank": true`.

## Layout

```
manifest.json
src/transliterator.js   # pure Singlish -> Sinhala engine, no DOM/chrome APIs
src/content.js          # converts as you type in page text fields, uses the engine
src/background.js       # service worker: Alt+Shift+S toggle, toolbar icon on/off state
popup/popup.html|js|css # converter box with Copy, collapsible key reference
icons/                  # icon*.png (on) + off-*.png (grey), generated by tools/make-icons.ps1
tests/*.test.js         # node:test unit tests for the engine
tests/harness.html      # test page for content.js in a normal browser (stubs chrome.storage)
tools/make-icons.ps1    # regenerates icons/
tools/package.py        # builds the release zip in dist/ (git-ignored)
```

`manifest.json` lists content scripts in order: `src/transliterator.js` then `src/content.js`. They share the page's isolated world, so the engine exposes itself on `globalThis.SinhalaTransliterator`. Content scripts can't be ES modules, so don't use `import`/`export` in them. The engine also does `if (typeof module !== 'undefined') module.exports = …` so Node tests can `require` it. The popup loads the same file through a `<script>` tag for its converter and key reference. The key grid is generated from the engine's `VOWELS`/`CONSONANTS` tables, so it never drifts from the real mappings.

## Transliteration engine (`src/transliterator.js`)

`transliterate(roman: string): string` is a pure function. All Sinhala knowledge lives in mapping tables in this one file, with nothing hard-coded elsewhere.

Algorithm: tokenize left-to-right using a **greedy longest match** against the tables (longest key first, currently 3 chars). Then render: **case matters** (`a`≠`A`, `l`≠`L`, `n`≠`N`).

- **Consonant + `a`** → the bare consonant (inherent vowel), e.g. `ka` → ක.
- **Consonant + another vowel** → consonant + dependent vowel sign (pilla), e.g. `ki` → කි, `kaa` → කා.
- **Consonant with no following vowel** → consonant + al-lakuna `්` (U+0DCA), e.g. `k` → ක්.
- **Consonant + `x`/`H`** → bare consonant + modifier, e.g. `kx` → කං, so the inherent vowel is kept.
- **Vowel at word start or after another vowel** → independent vowel letter, e.g. `amma` → අම්ම.
- **Conjuncts:** `y` and `r` directly after a consonant render as yansaya/rakaransaya using ZWJ (U+200D): `kya` → ක්‍ය, `kra` → ක්‍ර. The exception is ර followed by ර.
- **Unmapped capitals fall back to lowercase** (`Mama` → මම), so sentence-initial caps work. Keys that start with a capital (`A Aa R RR T D N L H Sh Th Dh`) keep their own meaning.
- Characters with no mapping (digits, punctuation, spaces) pass through unchanged.

Mapping conventions:

| Vowel | Independent | Sign | | Vowel | Independent | Sign |
|---|---|---|---|---|---|---|
| a | අ | (none) | | u | උ | ු |
| aa | ආ | ා | | uu | ඌ | ූ |
| A | ඇ | ැ | | e | එ | ෙ |
| Aa | ඈ | ෑ | | ee | ඒ | ේ |
| i | ඉ | ි | | ai | ඓ | ෛ |
| ii | ඊ | ී | | o / oo | ඔ / ඕ | ො / ෝ |
| R | ඍ | ෘ | | au | ඖ | ෞ |
| RR | ඎ | ෲ | | | | |

(`ru` is deliberately *not* ඍ, because that would break common words like රුව.)

Consonants: `k` ක, `kh` ඛ, `g` ග, `gh` ඝ, `ng` ඞ, `c` ච, `ch` ඡ, `j` ජ, `jh` ඣ, `ny` ඤ, `kn` ඥ, `t` ට, `T` ඨ, `th` ත, `Th` ථ, `d` ඩ, `D` ඪ, `dh` ද, `Dh` ධ, `N` ණ, `n` න, `p` ප, `ph` ඵ, `b` බ, `bh` භ, `m` ම, `y` ය, `r` ර, `l` ල, `L` ළ, `v`/`w` ව, `sh` ශ, `Sh` ෂ, `s` ස, `h` හ, `f` ෆ.
Prenasalized (sanyaka): `zg` ඟ, `zj` ඦ, `zd` ඬ, `zdh` ඳ, `zb` ඹ.
Others: `x` ං (anusvaraya), `H` ඃ (visargaya).

When changing the tables, check that greedy matching still splits ambiguous sequences correctly (`th`, `dh`, `zdh`, `kn`), and add tests for them. The README's typing guide repeats these tables for users, so update it too.

## Content script (`src/content.js`)

It converts **as you type**, word by word.

- Applies to `<textarea>`, `<input>` of type `text`/`search`/no type, and `contenteditable` elements. It never touches `password`, `email`, `url`, `number` or similar fields.
- Keeps a **roman buffer** for the word being typed, plus the Sinhala string last inserted for it (`state.out`). Before every edit it checks that `state.out` is exactly the text before the caret. If not (caret moved, page changed the text), it silently starts a fresh word. On a `keydown` of an ASCII letter: `preventDefault()`, append to the buffer, re-run `transliterate(buffer)`, then replace the previously inserted text with the new output. Re-rendering the whole word on each keystroke is what lets `k` → ක් turn into `ki` → කි.
- **Backspace** while the buffer is non-empty pops one roman char and re-renders. Once the buffer is empty, the browser handles it normally.
- **Commit (clear buffer)** on space, Enter, punctuation, digits, arrow/Home/End keys, mouse click, focus change, or any modifier combo (Ctrl/Alt/Meta). Let those events through untouched. Shift and CapsLock alone don't commit.
- Insert text with `document.execCommand('insertText', …)` after selecting the chars to replace. It keeps native undo working and fires the `input` events React/Vue/etc. depend on. Fall back to `setRangeText` (or DOM range edits for contenteditable) + a dispatched `InputEvent` when `execCommand` returns false.
- **Grapheme-cluster gotcha:** Chrome treats e.g. `ක්ම` as one cluster. When Sinhala text directly follows the edit point, `execCommand` widens the edit and deletes the following letter, and the caret snaps past it. So `followedBySinhala()` forces the exact-replacement fallback, and `restoreCaret()` puts the caret back after every insert. Keep both if you refactor the insertion code.
- Skip events where `e.isComposing` is true (another IME is active).
- Reads `enabled` from `chrome.storage.sync` on load and reacts to `chrome.storage.onChanged`, so toggling takes effect without reloading the page.

## Toggle and toolbar icon (`src/background.js`)

- State lives in `chrome.storage.sync` as `{ enabled: boolean }` (default `true`). This is the single source of truth. Only `background.js` writes it. The popup and content scripts only read it.
- The `toggle-conversion` command (suggested `Alt+Shift+S`) flips `enabled`.
- The toolbar icon shows the state: `icons/icon*.png` when on, the grey `icons/off-*.png` when off. **Don't use badge text.** It looked like a second icon on the toolbar button, so `updateAction()` clears it.

## Popup (`popup/`)

- A compact converter: type Singlish, then copy the Sinhala with the Copy button or Ctrl+Enter. Clear empties it. The draft is kept in `localStorage`, and the input is focused when the popup opens.
- **No on/off switch** (deliberately removed). The header shows a read-only status line ("Typing on pages" / "Paused on pages") next to an `Alt+Shift+S` hint.
- The header logo is the real icon file (`<img src="../icons/icon128.png">` at 32px), not a CSS recreation. A CSS version ended up off-center, so keep using the image.
- **Height budget:** Chrome caps popups at 600px tall, and the scrollbar is hidden (`::-webkit-scrollbar { display: none }`). The input and output boxes grow with their text (`autoGrow()` in `popup.js`) up to CSS max-heights of 140px and 260px, which keep the popup at about 585px with "Keys" closed. Past that, the output scrolls and follows the end of the text. "Keys" open with little text is about 570px (9-column grid). If you raise any of these, recheck the 600px limit.
- Light and dark themes come from CSS custom properties on `:root`, with dark values under `prefers-color-scheme: dark`.

## Icons (`tools/make-icons.ps1`)

- The style is a **flat maroon rounded square (`#8a1538`) with a bold white අ**. The off set is the same in grey. The user tried and rejected a bare letter, a speech bubble, a circle, a shield, a keyboard key and an embossed version, so don't change the style unless asked.
- The letter is centered on its **solid ink**: the script draws it once off-screen, finds the pixels with alpha > 200, then redraws it shifted. Centering the font's text box instead leaves it low and to the right. Counting faint anti-aliased edge pixels made the 32px icon 1px low. It uses `DrawString` (not a path fill) so the 16px icon keeps font hinting and stays crisp.
- After regenerating, check the margins at every size. They should be equal to within 1px.

## Commands

Run engine tests (Node 18+, built-in test runner, no install needed):

```bash
node --test
```

(Node 22+ treats `node --test tests/` as a module path and fails. Bare `node --test` auto-discovers `*.test.js`.)

Run a single test by name:

```bash
node --test --test-name-pattern="yansaya"
```

Try it in Chrome: open `chrome://extensions`, enable Developer mode, click **Load unpacked**, and pick the repo root. After editing, click the reload icon on the extension card and refresh the test page, because content scripts don't hot-reload. Service worker logs are under "Inspect views: service worker" on the card. Content script logs show in the page's DevTools console.

Test the content script or popup without installing the extension: serve the repo root with `python -m http.server 8765` (the `harness` config in `.claude/launch.json`).

- **Content script:** open `http://localhost:8765/tests/harness.html`. It exposes `typeInto(el, keys)`, which dispatches keydown events through `content.js` and returns the field's text. Synthetic events don't type non-letter keys, so the helper inserts those itself. Scripts are cache-busted, so a plain reload picks up edits.
- **Popup:** open `http://localhost:8765/popup/popup.html`. `popup.js` calls `chrome.storage` at load, so define a stub (`window.chrome = { storage: { sync: { get: (d, cb) => cb(d), set() {} }, onChanged: { addListener() {} } } }`), then re-run the script, e.g. `new Function(await (await fetch('popup.js')).text())()`. Re-injecting it with a `<script>` tag fails on duplicate `const` declarations.

Regenerate icons (Windows PowerShell 5.1, uses System.Drawing):

```bash
powershell -ExecutionPolicy Bypass -File tools/make-icons.ps1
```

## Releasing

1. Bump `"version"` in `manifest.json`. Releases are tagged `v<version>`.
2. Run `node --test`, then build the package:

   ```bash
   python tools/package.py
   ```

   This writes `dist/sinhala-typing-v<version>.zip` containing only `manifest.json`, `src/`, `popup/` and `icons/`, with forward-slash paths. It fails if anything the manifest, popup or background script references is missing. Don't use PowerShell 5.1's `Compress-Archive` instead, because it writes backslash paths. `dist/` and `*.zip` are git-ignored.
3. Tag the release commit and push the tag: `git tag -a v<version> -m "..."` then `git push origin v<version>`.
4. Create the GitHub release from the tag and attach the zip. The same zip is what you'd upload to the Chrome Web Store.

## Git workflow

- Work happens on a feature branch, with PRs into `main`. Don't commit directly to `main`.
- The GitHub CLI (`gh`) isn't installed on this machine. To open a PR or release, push the branch or tag, then give the user a prefilled URL: `https://github.com/pramod4lk/sinhala-typing-chrome-extension/compare/main...<branch>?expand=1&title=…&body=…` or `…/releases/new?tag=…&title=…&body=…`. You can check existing PRs without auth through the public API (`curl https://api.github.com/repos/pramod4lk/sinhala-typing-chrome-extension/pulls?state=all`).

## Known limitations

- Google Docs and other canvas-based editors don't use DOM text fields, so conversion doesn't work there.
- Caps Lock changes meaning, because keys are case-sensitive.
